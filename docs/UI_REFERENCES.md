# UI References

Version: 2.0\
Last Reviewed: 2026-09-16\
Status: Active reference policy

## Reference budget

For a substantial UI direction, use:

1. one platform authority;
2. up to two first-party interaction references;
3. at most one narrow supplementary craft reference when justified.

Do not build a reference collage.

## Platform authority

**Apple Human Interface Guidelines**

Use for interaction behavior, accessibility, navigation, layout adaptation,
system materials, control semantics, and platform conventions.

## First-party interaction references

**Apple Notes**

Use for content-first hierarchy, restrained navigation/chrome, text-centric
scanning, and a creation action that remains easy to find.

**Apple Mail**

Use for native list behavior, toolbar/action consistency, search/navigation,
and dense-but-readable content hierarchy.

These are behavior/grammar references, not templates.

## Flick anti-reference

Avoid:

- productivity-dashboard chrome;
- web-app cards transplanted unchanged into SwiftUI;
- generic AI gradient/chat aesthetics;
- excessive glass/material layers;
- sidebar-first taxonomy;
- gamified inbox-zero mechanics.

## Supplementary references

Any non-Apple visual reference must have a narrow stated purpose and may not
override HIG or Flick's native objective.
